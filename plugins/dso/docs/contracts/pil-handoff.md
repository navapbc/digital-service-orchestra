# Contract: pil-handoff

- Signal Name: pil-handoff
- Status: accepted
- Scope: /dso:brainstorm (emit) → /dso:preplanning and /dso:implementation-plan (consume)
- Date: 2026-05-18

## Purpose

The **Planning Intelligence Layer (PIL)** handoff is the structured data passed from the
`/dso:brainstorm` skill (emit side) to `/dso:preplanning` and `/dso:implementation-plan`
(consume side) via a `PREPLANNING_CONTEXT:` ticket comment on the epic.

This contract defines:

1. The canonical JSON schema for the `PREPLANNING_CONTEXT` payload (schema_version 2)
2. Which side writes which fields
3. Mutation rules (immutable vs enrichable fields)
4. Validation expectations and the `validate-pil-handoff.sh` interface

---

## Emit Side: `/dso:brainstorm` Phase 3 Step 3a

`/dso:brainstorm` writes a `### Planning Intelligence Log` ticket comment (Step 3a).
This is a human-readable record of the planning session and is **not** the structured
`PREPLANNING_CONTEXT:` payload.

The structured `PREPLANNING_CONTEXT:` payload is written by `/dso:preplanning` Phase H
Step 6 after story decomposition is complete. The brainstorm skill does **not** write
`PREPLANNING_CONTEXT:` directly; it sets up the epic for preplanning to do so.

---

## Consume Side: `/dso:preplanning` and `/dso:implementation-plan`

### `/dso:preplanning` — Phase A Step 3 (Audit Existing Children)

Preplanning reads the epic ticket comments and merges any prior `PREPLANNING_CONTEXT:`
or `RESEARCH_FINDINGS:` data before writing its own enriched `PREPLANNING_CONTEXT:`
comment in Phase H Step 6.

### `/dso:implementation-plan` — Context File Check

`/dso:implementation-plan` reads the last `PREPLANNING_CONTEXT:` comment on the parent
epic (within 7-day TTL) and, if valid, skips redundant Input Analysis. See
`skills/implementation-plan/SKILL.md` § Context File Check.

---

## PREPLANNING_CONTEXT Payload Schema (schema_version 2)

The payload is a single minified JSON line, prefixed with `PREPLANNING_CONTEXT: ` in
the ticket comment body.

### Top-Level Fields

| Field | Type | Required | Written by | Notes |
|-------|------|----------|------------|-------|
| `schema_version` | integer | **required** | preplanning | Must be `>= 1`. Current canonical value: `2`. |
| `version` | integer | optional | preplanning | Internal revision counter (currently `1`). |
| `epicId` | string | **required** | preplanning | The epic ticket ID (e.g., `f9de-b7d9-c23e-4f5b`). |
| `generatedAt` | string | **required** | preplanning | ISO-8601 timestamp of when this payload was written. |
| `generatedBy` | string | optional | preplanning | Always `"preplanning"` for payloads generated by this skill. |
| `epic` | object | optional | preplanning | Epic metadata. See [epic object](#epic-object). |
| `researchFindings` | array | optional | preplanning (merged from brainstorm) | Capability research findings. See [researchFindings array](#researchfindings-array). Absent or empty when schema_version < 2. |
| `stories` | array | optional | preplanning | Decomposed story list. See [stories array](#stories-array). |
| `storyDashboard` | object | optional | preplanning | Aggregate story stats. See [storyDashboard object](#storydashboard-object). |

### `epic` Object

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `title` | string | optional | Epic title as written in the ticket. |
| `description` | string | optional | Epic description body. |
| `successCriteria` | array of string | optional | Bullet items from the `## Success Criteria` section. |

### `researchFindings` Array

Each element:

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `capability` | string | required | Short description of the researched capability. |
| `status` | string | required | One of: `verified`, `partially_verified`, `unverified`, `contradicted`. |
| `source` | string | required | URL or citation for the finding. |
| `skill_name` | string | required | Which skill produced this entry (e.g., `preplanning`, `brainstorm`). |
| `timestamp` | string | required | ISO-8601 timestamp of the finding. |

### `stories` Array

Each element:

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `id` | string | required | Ticket ID for the story. |
| `title` | string | required | Story title. |
| `description` | string | optional | Story description body. |
| `priority` | integer | optional | Priority 0–4. |
| `classification` | string | optional | `new`, `reuse`, or `modify`. |
| `walkingSkeleton` | boolean | optional | Whether this is a walking-skeleton story. |
| `hasWireframe` | boolean | optional | Whether a design wireframe was produced. |
| `doneDefinitions` | array of string | optional | Acceptance criteria ("When this story is complete, …"). |
| `considerations` | array of string | optional | Tagged notes, e.g., `[Performance] …`. |
| `scopeSplitCandidate` | boolean | optional | Whether the story was flagged for possible split. |
| `splitRole` | string or null | optional | `foundation`, `enhancement`, or `null`. |
| `splitPairId` | string or null | optional | Paired story ID for split pairs; `null` when not split. |
| `blockedBy` | array of string | optional | Blocking ticket IDs. |
| `satisfiesCriterion` | string | optional | Verbatim quoted epic criterion this story satisfies. |

### `storyDashboard` Object

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `totalStories` | integer | optional | Total number of stories in the plan. |
| `uiStories` | integer | optional | Number of UI-facing stories. |
| `criticalPath` | array of string | optional | Ordered list of story IDs on the critical path. |

## Mutation Rules

### Immutable Fields (must not be changed after first write)

| Field | Rationale |
|-------|-----------|
| `epicId` | Identity anchor; changing it would break consumer lookups. |
| `schema_version` | Governs parse logic in consumers; must remain stable within a payload. |
| `generatedAt` | Timestamp provenance; represents when the payload was created. |

### Enrichable Fields (preplanning may update or extend)

| Field | Allowed enrichment |
|-------|-------------------|
| `researchFindings` | Preplanning **merges** prior `RESEARCH_FINDINGS:` comments into this array; it may append new entries but must not remove existing ones. |
| `stories` | Preplanning populates this after story decomposition; may be extended by re-runs. |
| `storyDashboard` | Recomputed on each preplanning run to reflect the current story set. |
| `epic.successCriteria` | May be enriched with resolved criteria as planning proceeds. |

### Forward-Compatibility Rules

- Consumers **must** ignore unknown top-level fields (open-world assumption).
- Consumers **must not** reject a payload solely because it contains extra fields.
- `schema_version` governs behavioral branching (see below).

---

## schema_version Parsing Logic

| `schema_version` value | Consumer behavior |
|------------------------|-------------------|
| Absent or `< 2` | v1 mode: `researchFindings` not expected; treat as empty array. |
| `>= 2` | v2 mode: `researchFindings` expected; if absent, treat as empty (fail-open). |

Consumers must not hard-code a specific version number — use the `>= N` comparator pattern.

---

## TTL and Staleness

Consumers should treat a `PREPLANNING_CONTEXT:` comment as stale when:
- `generatedAt` is more than **7 days** old (configurable by consumer).

When stale, the consumer must run full Input Analysis rather than relying on cached context.

---

## Validation

The `validate-pil-handoff.sh` script enforces the minimum required-field contract:

```bash
# Validate via stdin:
echo "$PREPLANNING_CONTEXT_JSON" | bash "${CLAUDE_PLUGIN_ROOT}/scripts/validate-pil-handoff.sh"

# Or via file:
bash "${CLAUDE_PLUGIN_ROOT}/scripts/validate-pil-handoff.sh" --pil-file=/path/to/payload.json
```

**Required fields checked**: `schema_version` (integer ≥ 1), `generatedAt` (non-empty string),
`epicId` (non-empty string).

**Exit codes**:
- `0` — payload is valid
- `1` — validation failed; JSON error object written to stderr

**Fail-open contract**: validation errors must not block preplanning. Log the error and continue.
