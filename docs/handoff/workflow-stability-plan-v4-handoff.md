## 1. Goals (target process)

1. **Every code change passes an LLM review before it merges to main.**
2. **LLM reviews happen on smaller PRs that merge into `staged-*` branches.**
3. **`staged-*`→main PRs are the only PRs that merge to main.** Each gets an LLM "integration review" covering **only** changes (a) not already on main and (b) not already reviewed by the sub-PRs.
4. **Admin override is the safety valve** for bugs / LLM false positives, performed by a **human via the GitHub web UI** — the autonomous local dev agent must not be able to self-bypass.
5. **`dso.workflow` controls the mode**: `ci-pr` = this staged/CI process; `local` = LLM review runs before each commit, enforced by a pre-commit hook review gate.
6. **`fp-recovery` handles** (a) recovery of a failing PR (record audit evidence, then give the user a web-UI merge link) and (b) **post-hoc audit** after an admin already merged a PR bypassing the process (only when LLM review was skipped or failed on that PR).

In the 20-PR sample this narrowing **always fired** (full-diff fallback never triggered) — so Goal 3's delta scoping is real in practice.
- **CS-10 (chronic-bug root cause)** The commit-scoped diff is built by **concatenating per-commit `git show` output**: `git show --format= --diff-merges=first-parent "$_sha"` appended for each unprovenanced SHA `[code:llm-review-dispatch-or-skip.sh:414-419]`. This is **NOT a net `git diff base..head`** — so when commit A introduces a problem and a later in-range commit D fixes it, **both hunks appear** and the reviewer flags the intermediate state. ## 3. Target state (per goal)

- **TS-1 (G1/G2) — LIVE HOLE confirmed by P9.** Today, two places equate **reachable-from-`origin/main`** with **reviewed**, with no review-check verification: the dispatcher's `comm -23` scope filter (`llm-review-dispatch-or-skip.sh:385`, SKIP at `:401-412`) and the verifier's `^origin/main` walk exclusion (`verify-session-provenance.sh:357,647`). Consequence: **any SHA that reaches main unreviewed (admin bypass, hotfix, or a prior slip) is permanently "laundered"** — on every later PR it is silently filtered out and never reviewed. (Path 1 direct-on-staged is closed; Path 2 squash/reachable is the open hole; Path 3 admin-bypassed sub-PR is caught on its first PR by G3 but re-laundered by Path 2 thereafter.) The liveness net can't catch it — `assert-review-liveness.sh:47-78` validates JSON *shape*, and every SKIP writes a satisfying stub.
  **Concrete invariant**: a SHA leaves review scope **iff** a covering PR has a `success` (poison-on-failure) `review-sub-pr`/`llm-review` check-run — *proven by check-run lookup, never inferred from reachability to `origin/main`*. Implement as a new **required** check `review-coverage-invariant` that (1) resolves the full `base..head` SHA set with **no** reachability/`comm` prefilter; (2) reuses the existing G3 routine (`verify-session-provenance.sh:524-634`) as the `reviewed(s)` predicate (it already proves "passing review check-run on a covering PR" — the bug is only that the reachability filters short-circuit before it runs); (3) keeps a durable, CI-written **reviewed-SHA ledger** storing *reviewed=true + check-run URL* (never *present-on-main*), with reachability allowed only as a perf prefilter that still requires a ledger hit to skip; (4) **fail-closes** on any API error / `not_found` / shallow / ambiguity; (5) makes `assert-review-liveness.sh` **reject skip stubs** (`all_scope_already_merged` / `all_commits_provenanced`) unless coverage is independently confirmed.
- **TS-2 (G3)**: only `staged-*`→main PRs merge (live ✓ via `check-staged-head`); the integration review covers the un-reviewed delta, reviewed as the **net end-state** of the in-scope commits, with the full test suite on the combined staged state as the semantic-conflict backstop.
- **TS-3 (G4)**: the dev agent runs under a **non-bypass-actor identity**; no agent path (UI/CLI/API) can merge to main; a named human bypasses via the web UI.
- **TS-4 (G5)**: `ci-pr` and `local` both guarantee "no unreviewed merge" at their enforcement points (server-side ruleset vs client-side pre-commit gate — the asymmetry is documented).
- **TS-5 (G6)**: fp-recovery emits a clearance + web-UI merge link (no agent `--admin`) after verifying all *other* required checks are green; a post-hoc audit sweep retroactively reviews already-merged PRs whose `llm-review` was skipped/failed and records a tamper-evident (HMAC-signed) marker.

## 5. Industry validation (research)
- **Converge**: two-stage gating (small-PR review → separate integration gate before promoting trunk) is universal (bors, Prow Tide, Zuul, GitHub Merge Queue, Mergify, Graphite). Capability containment via reviewer-identity ≠ author-identity is the load-bearing control across LLM-review setups (CodeRabbit, etc.). Our staged-branch model + identity-based override match accepted practice.
- **Diverge**: mature merge queues re-validate the **combined** state at integration; we review the **delta**. Acceptable **because** the full test suite runs on the combined staged state as the semantic-conflict backstop — but a combination-only conflict across single-sub-PR files with no test coverage can slip both (→ W6).
- **Gotchas designed against**: required-check deadlock (sentinel/umbrella — mostly present, W5); flaky/non-deterministic LLM verdicts (cycle cap + convergence — W2c); all-or-nothing bypass skips *all* checks incl. tests (fp-recovery must verify others green — W3d); context overflow / OVER_BOUND (W2a net-diff shrinks it).

## 9. Rejected approaches / what NOT to do (corrected understandings — do not re-propose)
- **Do NOT broaden the sub-PR ruleset include to `~ALL`** (v3's fatal premise; `staged-*` is canonical; `sync-sub-pr-ruleset.sh` must be neutralized — CS-16).
- **Do NOT treat content-fingerprint defense carry-forward as the integration fix** — defenses are never loaded at integration (CS-11), the GitHub backend doesn't write the fingerprint, and `pr_number` in the hash prevents cross-boundary matching (CS-12). The fix is diff construction (W2a).
- **Do NOT rely on `bypass_mode: pull_request` for "web-UI only"** — it doesn't restrict the tool (CS-6); only a non-bypass-actor identity contains the agent.
- **Do NOT assume `ruleset-design-invariants` protects anything today** — it is inert (CS-4 + CS-17).
- **Do NOT trust comments/docs over live `gh` config and executable code** — the v3 failure and the W2 mis-diagnosis both came from trusting comments.
- **Do NOT build a `review-defenses-cleared` companion check** — redundant with the existing `llm-review` severity gate.
